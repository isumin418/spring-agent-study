## Why

클라이언트에서 등록된 게시글을 다시 조회할 수 있도록 작성 API와 이어지는 목록 조회가 필요하다. 빈 목록 응답과 기본 정렬을 명세에 정해 클라이언트가 일관되게 처리할 수 있게 한다.

## What Changes

- `GET /posts`에 래퍼 없는 JSON 배열을 제공한다.
- 항목은 작성 응답에서 공개하는 `id`, `title`, `content`로 한정한다.
- 저장된 게시글이 없으면 빈 배열을 반환하고, 게시글이 있으면 ID 오름차순으로 반환한다.
- 범위는 목록 조회에 한정한다. 페이징, 필터, 클라이언트 지정 정렬, 상세 조회는 범위에서 제외한다.

## Capabilities

### New Capabilities

- `post-list`: 등록된 게시글 목록 조회

### Modified Capabilities

없음.

## Impact

기존 인메모리 저장소를 조회 입력 포트와 출력 포트를 통해 사용한다. 작성 API의 요청·응답 및 저장 동작을 유지한다.
