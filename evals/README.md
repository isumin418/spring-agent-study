# Skill 평가

[OpenAI의 Skill 평가 가이드](https://developers.openai.com/blog/eval-skills)를 따라 선택 여부, 구현된 동작, 테스트 결과, 요청 범위 준수를 각각 평가한다. 명시적 호출, 암묵적 호출, 맥락이 있는 요청과 부정 대조군을 같은 초기 상태의 별도 사본에서 실행한다.

| 사례 | 요청 | 기대하는 Skill 선택과 변경 |
| --- | --- | --- |
| 명시적 | “$change-post-creation을 사용해 게시글 제목을 최대 100자로 제한해줘.” | 선택. 100자는 허용, 101자는 400. 관련 동작 및 ArchUnit 테스트 실행·통과. |
| 암묵적 | “게시글 작성 시 제목이 100자를 넘으면 400을 반환하도록 수정해줘.” | 선택. 100자는 허용, 101자는 400. 관련 동작 및 ArchUnit 테스트 실행·통과. |
| 맥락 포함 | “프론트에서 제목 앞뒤에 공백이 붙어 들어와. 게시글을 저장하기 전에 제목 앞뒤 공백을 제거해줘.” | 선택. 저장 전 제목 양끝 공백 제거, 201 응답에도 제거된 제목이 반환됨. 내용 보존. 관련 동작 및 ArchUnit 테스트 실행·통과. |
| 부정 대조군 | “README 소개 문구만 두 문장으로 줄여줘.” | 미선택. README 소개만 변경. Java 및 테스트 파일 변경 없음. 테스트 실행은 필수 아님. |

## 판정 방법

- `codex exec --json`의 도구 이벤트에서 해당 Skill의 `SKILL.md` 읽기 등 직접 증거를 찾는다. 기록이 불충분하면 **확인 불가**로 표시한다. CLI 실행을 할 수 없으면 **미실행**으로 표시한다.
- 각 사본의 Git diff에서 요청 동작과 변경 범위를 확인한다. Gradle 명령 이벤트의 종료 상태와 JUnit 리포트에서 실행 및 통과 여부를 확인한다.

## 실행 결과

Codex CLI `0.167.0-alpha.3.2`에서 `codex exec --json`을 네 번 실행했다. 동일한 기준 커밋을 각각의 임시 Git 저장소에 만들고, Skill 평가에서 Hook 실행의 영향을 제외하기 위해 CLI에서 Hook을 비활성화했다.

| 사례 | Skill 선택 증거 | 변경 확인 | 테스트 결과 |
| --- | --- | --- | --- |
| 명시적 | 선택. `SKILL.md` 읽기 기록 | 제목 100자는 201, 101자는 400 | CLI에서 재시도 후 통과. 별도 검증에서도 API 11개와 ArchUnit 3개 통과. |
| 암묵적 | 선택. `SKILL.md` 읽기 기록 | 제목 100자는 201, 101자는 400 | CLI에서 Gradle 실행을 시도했으나 접근 제한으로 완료하지 못함. 별도 검증에서 API 10개와 ArchUnit 3개 통과. |
| 맥락 포함 | 선택. `SKILL.md` 읽기 기록 | 저장 전 `strip()` 적용. 응답의 제목 양끝 공백 제거 및 내용 보존 | CLI에서 Gradle 실행을 시도했으나 의존성을 확인하지 못함. 별도 검증에서 API 10개와 ArchUnit 3개 통과. |
| 부정 대조군 | 읽기나 호출 흔적 없음. 내부 선택 여부는 확인 불가 | Git diff에서 README 소개만 두 문장으로 변경. Java 및 테스트 파일 변경 없음. | 실행 기록 없음. |

JSONL 원본과 평가용 diff는 로컬 임시 경로 `%TEMP%\cleanlab-verification`의 `eval-01.jsonl`~`eval-04.jsonl` 및 각 `eval-0N` 사본에서 확인할 수 있다. 별도 검증은 같은 사본에서 `.\gradlew.bat test --offline --no-daemon`으로 실행했다.
